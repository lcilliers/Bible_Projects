**DBSchema register maintenance**

## What it configures

The rules for capturing a database's schema into a DBSchema register, and the list of the databases that get one. The registers live in ../DBSchema/, ONE FILE PER DATABASE. Today there is one (bible_research); the new IBA database will be the second, and its arrival is an entry in ent.dbschema.database -- not a code change.

**Boundary**

- `util.dbschema (this file)` — WHAT a schema register holds and HOW it is captured and kept current.
- `util.db (db.json, pending)` — HOW a database is reached -- connection, transaction, backup. A different subject.

**Nodes**

- `process` — How a register is captured: from the live DB, descriptions from the data, preserve on rebuild, retire never delete.
- `entities` — The database list -- the registry that makes this multi-database.
- `output` — The register files themselves.
- `validation` — The gates: read-only source, counts match, staleness visible.
- `naming` — Naming parameters.
- `filing` — Filing parameters.
