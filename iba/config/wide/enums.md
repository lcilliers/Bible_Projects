THE REGISTER OF CONTROLLED VOCABULARIES. Every word-group / lookup used anywhere in IBA is defined here, once, and assigned a code — and nowhere else. - **`meta.open.value-metadata`** — A value is a bare string. There is no per-value home for its meaning, its ordinal, or its aliases — so enum.segment_unit_type invented a side-map (`labels`), enum.role's aliases sit in a separate `alias_map`, and every other vocabulary's values are simply undefined. The plan's cfg_enum table expects value + ordinal + notes (A.3), which this shape cannot supply.
  - _recommendation:_ B, decided BEFORE expansion — the register is 11 of ~50+ items; changing the value shape after authoring the rest is the expensive order. Applying your own self-interpretable rule to the config is also the consistent one.
  - _resolve by:_ researcher decision
- **`meta.open.legacy-scope`** — The plan's new DB carries no legacy (3.4.2 'no legacy/quarantine carry-over'), but the envelope defines a LEGACY status and the README says superseded rules are marked, not deleted. It is not decided whether pre-reset vocabularies (session_b_status, cluster.*, the pre-reset flag sets) belong in this register as LEGACY or are simply out of scope.
  - _recommendation:_ B for anything the new DB never stores, A for anything that arrives with the migrated registry/term layer (those values will be present in new-DB rows, so the new config must define them).
  - _resolve by:_ researcher decision
- **`meta.open.source-of-members`** — For most outstanding vocabularies the authoritative member list is in the live DB (wa_vocab_set/wa_vocab_member) or a SQL CHECK, not in a doc.
  - _resolve by:_ Pull members from the live DB once, as a one-time seed extraction, and author from that — per recon.vocab-home's recommendation. Needs a read-only extract script before expansion.
