**Raw data**

## What it configures

The raw data layer — external-source data held exactly as the source gave it: verse text, verse morphology, and the Strong's lexicon. This process owns WHAT RAW IS and the controls that let it be trusted; it owns no interpretation whatsoever.

**Nodes**

- `process` — How the layer works — immutability, provenance stamping, what qualifies as raw, and the boundary against `fetch` (which retrieves) and `base` (which derives).
- `entities` — The data it owns: verse · verse_morphology · lexicon. Definitional only — what each entity IS and how they relate. It does NOT declare tables or columns; that is the schema's job (layout v2 §1).
- `output` — What the layer emits for human consumption. Raw emits almost nothing — it is consumed, not published.
- `validation` — The ingest controls. Source-parity, completeness, no-null, FK integrity. Mostly db:*-enforced.
- `naming` — This process's naming parameters.
- `filing` — This process's filing parameters.

## Code it serves

- `module` — module.raw
- `note` — One stage, one module, one file. The pipeline says WHEN raw runs and in what units; this file says what its rules are.

**3 open question(s)**

- **`open.raw.step-parity`** — `gate.raw.source-parity` is stated but has no mechanism: STEP is a live local server with NO cache, so re-querying it later is not a stable baseline to compare against — the source can change under us and we would not know.
  - _recommendation:_ A — it makes raw genuinely replayable and is the only option that survives STEP changing or going away. It is also what 'raw is immutable' actually requires: you cannot assert immutability against a source you did not keep.
  - _resolve by:_ researcher decision
- **`open.raw.migrated-provenance`** — The plan migrates the live DB's raw layer as-is, stamped `migrated-from-<old>@<date>` (3.4.1). But that data's TRUE provenance is a STEP fetch of unknown date, made under the old engine.
  - _recommendation:_ Stamp both: `source` = STEP (+ fetch date where recoverable, else `unknown`), `migrated_from` = the old DB. Never let the migration stamp masquerade as the origin.
  - _resolve by:_ researcher decision; affects the migration module
- **`open.raw.correction-cascade`** — raw.step-precedence means stored raw CAN change. But interpretations were made against the old value — a lexical read cites a span whose morphology or gloss may now differ. Nothing currently detects that.
  - _recommendation:_ A now, C as the model. B is too blunt — a gloss typo fix should not invalidate a book. But note the cascade is REAL and already latent: the multi-code fix (open.step.multi-code-fork) will add 144 verses to ruach alone, and every existing ruach read was made without them.
  - _resolve by:_ researcher decision — arises directly from the 2026-07-15 precedence ruling
