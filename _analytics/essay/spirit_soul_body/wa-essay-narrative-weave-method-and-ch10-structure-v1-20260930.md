## 1. The two dangers this design guards against

1. **Loss by fit-checking.** A new observation is tested against the current narrative. What supports it goes in; the rest is quietly left out. The narrative then only ever confirms itself.
2. **Ch 10 as a dumping ground.** Every cluster strand (fear, anger, doubt, thought, will, speech, memory, desire, the hands …) describes an *operation*. Ch 10 is organised by operation, so everything lands there. Today it is 1,625 words in 7 sections. At this rate it will become unreadable, and connections between operations will be buried.

## 2. The weaving method (every strand, every time)

### 2.1 Strand observation ledger — nothing is lost

Each strand keeps one ledger file beside its sources, e.g. `_analytics/cross-cluster-web/origin-of-thought/origin-of-thought-observation-ledger-v1-{date}.md`. There is one row per observation:

| Column | Content |
|---|---|
| id | e.g. `OT-07` |
| observation | what the verses show, in plain words |
| verses | references (ESV-checked before weaving) |
| touches | every chapter/section it bears on, not just the best one |
| disposition | **woven** (where) · **reshapes** (which existing text changes, and how) · **new structure** (needs a new section/chapter) · **held** (why: unverified, not yet pulled, science) |
| status | open / woven in chapter vN |

**Invariant:** every row has a disposition. **"Does not fit" is not a disposition.** If an observation has nowhere to go, the structure is what is missing, so the row becomes **new structure** and it is raised to you. It is not dropped.

### 2.2 Two passes, in both directions

1. **New → narrative (weave).** Each observation goes into every place it touches. It may appear in more than one chapter, each time in the light that chapter needs.
2. **Narrative → new (adjust).** Re-read every section the strand touches and ask: what does this section say that the new strand shows to be incomplete, too narrow, or wrong? Those sections are **rewritten**, not appended to. Each change goes into the claim register (verdict *Widened* / *Restated* / *Withdrawn*), in the same pass.

### 2.3 Structure log

The index (`00-index-and-status`) gains a **structure log**. Each time a strand forces a structural change (new section, split, move, new chapter), the log records the date, the strand, the change and the reason. That way the book's shape visibly follows the evidence.

## 3. Chapter 10 — built to grow

### 3.1 Proposal: Chapter 10 becomes a Part

**Part 10 — *The inner being at work*.** It has:

- **10.0 *How the inner being works*.** A short opening file. It maps the operations and, above all, **how they connect**: one operation leads into, feeds, or blocks another. This is where the web is visible. It is rewritten as each strand adds connections.
- **One file per operation**, added and grown as strands arrive. Starting set, from today's sections plus this strand:
  - 10.1 Feeling
  - 10.2 Knowing and hearing
  - **10.3 Thinking** (new — option B)
  - 10.4 Wanting
  - 10.5 Choosing and setting direction
  - 10.6 Right and wrong
  - 10.7 Relating to God
  - 10.8 Relating to others

  Later strands add operations of their own, or split existing ones (e.g. Speaking, Remembering, Acting with the hands). The list is **not** fixed in advance.

  > **As built at step 3 (2026-09-30):** Speaking was approved (NS-1) and inserted as **10.4**, so Wanting … Relating to others became **10.5–10.9**. Remembering is on watch (NS-2). The current numbering lives in the index's Structure log, not in this list.
- **File names** `10-03-thinking-v1-{date}.md` etc. Inserting an operation never renumbers Chapters 11–14.

### 3.2 What each operation file must carry — and what it must not

- **Must:**
  - a **"Connections"** passage naming the other operations it leads into or is fed by, with the verses that show it (this keeps the web from fragmenting into separate essays)
  - a pointer to the ledger rows it carries
- **Must not:** a fixed template of sub-headings to fill in. The shape of each operation is read from the verses, not imposed (the phenomenon-level, emergent rule). Two operation files may look quite different.

### 3.3 What stays out of Part 10

- **Seats** (heart, soul, spirit, flesh, conscience) stay in Ch 3–7. Part 10 refers to them.
- **Patterns** that cut across several operations (e.g. "one word, opposite values") stay in Ch 11.
- **Going wrong** and **being made new** stay in Ch 12 and 13. An operation file points to them and carries only what is specific to that operation.

### 3.4 Open structural question (for you)

The **thought-to-deed path** (arising → lodging → reckoning → devising → speech → hand and feet; Mic 2:1 against Ps 119:59) runs *through several operations*: thinking, speaking, choosing, acting. Where should it live?

- **(i)** In **10.0** as the first worked example of operations connecting. This is my leaning, because the path *is* the web in motion.
- **(ii)** In **10.3 Thinking**, with the other operations pointing to it.
- **(iii)** In **Ch 11** as a pattern.
