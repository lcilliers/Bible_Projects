## 1. The flow in practice, once built (M18 Desire & Longing as the example)

**A. Before analysis: at the clustering stage (E3a).**
1. `iba/app/ps/Cluster-Assign.ps1` runs as it does today: codes into clusters (`cluster_strong`).
2. A new step, `cluster.surface_map`, runs per M cluster (T-2). For M18 it:
   - lists the 454 (code, surface) pairs with their hits;
   - sets the cluster's surface groups, for example S1 desire to S12, as in the step 8 trial
     (`outputs/escalation/2286-m18-surface-vs-gloss-groups-v1-20261025.md`). These are
     `cluster_subgroup` rows, each with a kind: `group`, `qualifier` (E4: S8 good, better, well),
     `not_this_sense` and `anomaly` (C4);
   - allocates each pair to one group with its reason (C1). Pairs that fit no group go to the anomaly
     group (C4);
   - flags the two-sense pairs, such as *ṭôb* rendered "please" (C2);
   - runs a size check per group (C4);
   - marks every allocation provisional (C3).
3. `cluster.validate` reports any M pair with no group, and any pair whose code has left its cluster.
   While a cluster has stale pairs, `reading.open` refuses it (C5).

**B. A work unit (0.C).**
4. The researcher asks for a scope, for example "M18, group S2 delight". The resolver goes subgroup →
   (code, surface) pairs → the `verse_lexical` rows that carry them. It is exact to the occurrence,
   and it never uses `word_strong` (S4).
5. The output JSON lists, for each verse, all of its occurrences: code, surface, subgroup, cluster,
   the two-sense flag and whether the occurrence is in the home group (S1+S2). The other subgroups in
   the verse are shown, to be read (S5). They don't add verses to the scope. T-coded occurrences come
   in as context (T-b).
6. A `qualifier` group (S8) is not opened as a home scope of its own (E4).

**C. The reading.**
7. Each new node records the occurrence it reads (`verse_lexical.id`, S3). Reading Psa 51:10 for one
   subgroup then leaves it unread for the others (#2262).
8. A flagged pair settled in a verse is recorded on that occurrence with its reason (C2). A pair the
   reading moves to another group is recorded with its reason (C3).
9. A T-coded word found to be the characteristic in a verse is added by the reading to the cluster and
   its subgroup, with the reason (T-a, rule 70). That is a cluster change, so step 3 applies (C5).
10. Claims: duplication is grouped in `ib_observation` as it is today. Nothing new is needed.

## 3. The build units

Each unit is its own escalation task under #2286. Each is tested on a copy made by
`iba/app/lib/dbsnapshot.copy_db`, with the result recorded on its task (B:97). Every cfg write goes
through `apply_logged` (rule 75) and registers itself (rule 62). `iba/app/BUILD.md`,
`iba/app/USER-GUIDE.md` and `iba/app/GOVERNANCE.md` are updated in the same unit as the change they
describe.

| unit | what it builds | after | carries |
|---|---|---|---|
| **U1 config** | The rulings as cfg rows, each worded as its ruling: E1, E2, E3a, C1 to C5, T-1, T-b, T-c, T-2, S1 to S5, E4. Settings: the size limit per group, the head/tail cut, the API used for the tail. | none | B:31; S4 gap on #2287 |
| **U2 schema** | `surface_subgroup` (sketch below). A `kind` column on `cluster_subgroup`. `occurrence_subgroup` for per-verse settlements and moves (B4). `verse_lexical_id` on `ib_node`. All registered in `cfg_table`, `cfg_column`, `cfg_unique` and `cfg_write_grant`. | U1 | E2 |
| **U3 mapping step** | `cluster.surface_map` in `cluster-assign`, preview and live, run on one cluster or all of them. It covers group setting, head allocation, the API tail, the anomaly group, the size check and the two-sense flag. | U2 | E3a, C1 to C4 |
| **U4 enforcement** | `cluster.validate` reports stale and unmapped pairs. `reading.open` refuses a cluster that has them. | U3 | C5; with #2281 |
| **U5 resolver** | Paths a to f rebuilt to step 11, giving the occurrence-shaped JSON with a version field. The four callers move to it. Scope items resolve. The word path goes through the surface only. | U2, U3 | S1, S2, S4, S5; #2287; with #2276 |
| **U6 occurrence record** | `reading.record` writes `verse_lexical_id`. The 16,295 uniquely matched nodes are backfilled; the 606 others are listed (B6). Gap analysis counts per occurrence. | U2, U5 | S3; #2262 |
| **U7 T-a addition** | One app command: a reading adds a T code to a cluster and its subgroup, with the reason. It sets off U4's remap. | U3, U4 | T-a, rule 70 |
| **U8 pilot, then bulk** | M18 is mapped on the copy, timed, and compared with the step 8 trial (12 groups, 454 pairs). The other 79 M clusters follow once M18 is accepted (B7). | U3, U4 | E3a |

**Order:** U1 → U2 → U3 → U4 → U8 pilot (M18) → U5 → U6 → U7 → U8 bulk. The pilot puts M18's mapping
in front of the researcher before the resolver and the reading record are rebuilt on it.
