## The method

### 1. A check either fails, or says nothing

`configmaint.validate` drops its advisory tier: no acknowledged findings, and no counts carried
from run to run.
- Every check whose rule must hold becomes an **error**. Validate fails until the error is fixed,
  in the same session.
- A check with no rule behind it, or whose finding never leads to a fix, is **removed**.
- A run that finds nothing prints one line: coherent.

With no advisory tier, #2206 option 1 (only ask about new findings) is no longer needed. It is
removed in the same build.

### 3. Trap Claude's errors where they happen

1. **Before the action:** the point-of-use hook from #2209 shows the rules and usage of each
   operation. It is already live.
2. **When an action fails:** a new `PostToolUse` hook records each of Claude's failed calls with its
   operation and error text, in a session file. Not a count: one line per failure.
3. **At session close:** the close lists the session's failures. A failure of the same kind as an
   earlier one is a defect. It is fixed at its point of use: a missing rule link, a wrong USER-GUIDE
   line, or a tool that should refuse the call outright. It is not just reported.

This session would have trapped, for example, the three `Raise` attempts, the `-NextAction noted`
refusal and the `git commit -F -` failure. Each of those becomes one fix, not a lesson to remember.
