Redefinition of the IBA study, settled in discussion 2026-07-20. Authoritative trace =
[`iba/docs/iba-application-plan-v2-20260720.md`](iba/docs/iba-application-plan-v2-20260720.md) **§13**
(the plan's §§2–12 are first-pass reasoning; §13 governs where it differs).

**The output is a spiderweb of distinct, linked things — not one concordance:**
1. Evidence (built) = the span/Strong occurrence table.
2. The core study act = decide whether a Strong **in context** is inner-being or not (an *inclusion* decision).
3. **Three parallel concordances:** IB characteristics in operation · **other beings** (God, Jesus, Holy
   Spirit, Satan, spirits, angels, objects/idols) in operation with the IB *from the other being's
   perspective toward it* · the **human physical body** (hands, eyes, feet…) in operation with the IB.
4. Lexical layer = every reference verse/passage carries a lexical (preset dimensions, original-language
   grounded; several verses may share one).
5. A searchable, groupable **index** (a view over the concordances) — still undefined by intent.

Grain = a *distinct observation of a characteristic in operation* (not just what it is), anchored on the
main verse + passage ref, **cross-referenced never duplicated**, linked to verse/similar verses/related
characteristics/its lexical.

**The real discovery is the PROCESS, not the output** — how we read/digest/augment/refine, the most
elusive part of the study. The shift: **away from bulk-update (decide one rule, sweep it over everything)
→ toward locality (build the output deeply for a specific unit, then back-fill/augment prior work in the
same area on return).** The growing concordance exists to make augment-in-place possible.

**Why:** bulk-update is the study's most-repeated failure (method rebuilt 4–5×, each sweep discarded prior
learning). Output-structure and process are one idea. Also: the reading **unit varies by operation**
(chapter for prepare-read → candidate list; Strong(s) for analyse; passage is an *output*; resumable;
multi-phase prepare-lexicon→assemble-meaning→reconcile). **Recording ≠ reconciling** (two separate
actions; reconcile needs rules + surfacing + repair + a reviewable output). The app-only rule (§1.2) binds
**Claude Code too** — no direct SQL to `iba.db` outside a defined operation.

**How to apply:** treat the IBA build as unit-focused accretion, never a corpus-wide rule sweep. Next task
